#### Лекция 1.  Роль ИИ-инженера и жизненный цикл ИИ-систем
1. Бизнес-задача
Описание: Снизить финансовые потери банка от мошеннических транзакций, 
          сохранив удобство для клиентов (минимизировать ложные блокировки)
Роль:     Бизнес-заказчик, Аналитик
Риск:     Слишком жёсткие правила → рост жалоб и отток клиентов

2. ML-задача и метрика
Описание: Классификация риска транзакции (approve / review / block) 
          + генерация понятного объяснения. 
          Метрики: Precision high-risk, Recall, AUC-PR, Latency p95
Роль:     Data Scientist, ML Engineer
Риск:     Оптимизация только по Accuracy при сильном дисбалансе классов

3. Данные
Описание: История транзакций клиентов за 90–180 дней 
          (сумма, время, устройство, гео, merchant, поведение пользователя, метки фрода)
Роль:     Data Scientist, Аналитик
Риск:     Data drift, отсутствие разметки новых схем мошенничества (категория: Данные)

4. Эксперименты
Описание: Сравнение baseline-правил, LightGBM/CatBoost и нейросети. 
          Логирование параметров, метрик, SHAP и feature importance в MLflow
Роль:     ML Engineer
Риск:     Отсутствие воспроизводимости экспериментов

5. Тестирование
Описание: Устойчивость к крайним случаям (крупная сумма ночью, новая география, 
          смена устройства), контрактные тесты API, проверка качества объяснений
Роль:     ML Engineer, AI/MLOps Engineer
Риск:     Модель хорошо работает на истории, но ломается на новых паттернах

6. Деплой
Описание: Синхронный вызов ML-сервиса из платёжного шлюза (stream). 
          Версионирование модели + canary/shadow-деплой
Роль:     AI/MLOps Engineer
Риск:     Сложно и дорого встроить в существующий процессинг банка (категория: Интеграция)

7. Мониторинг
Описание: Доля блокировок и ручных ревью, latency, data/feature drift, качество объяснений, бизнес-метрики потерь
Роль:     AI/MLOps Engineer, Аналитик
Риск:     Никто вовремя не заметит, что модель деградировала (категория: Мониторинг)
