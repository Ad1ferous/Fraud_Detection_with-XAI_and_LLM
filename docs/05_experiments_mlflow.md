## Цель эксперимента
Мы провели 5 запусков обучения модели CatBoost для задачи детекции мошеннических транзакций, чтобы понять, как разные гиперпараметры влияют на качество поиска фрода. Все параметры, метрики и артефакты фиксировались через MLflow.

## Что мы делали в Colab
1. Сгенерировали синтетические данные с дисбалансом классов (~5.5% фрода), имитирующие реальные банковские транзакции.
2. Обучили модель 5 раз, меняя гиперпараметры: глубину дерева (`depth`), скорость обучения (`learning_rate`) и, самое главное, вес положительного класса (`scale_pos_weight`).
3. В каждом запуске (run) логировали:
   - **Params:** настройки модели.
   - **Metrics:** ROC-AUC, Recall и F1-score.
   - **Artifacts:** файл модели и график важности признаков (`feature_importance.png`).

## Результаты 5 запусков (Сводная таблица)
*(Данные получены через `mlflow.search_runs()`, отсортированы по метрике Recall)*

| № Run | Имя запуска | Параметры (Params) | Метрики (Metrics) | Комментарий |
| :--- | :--- | :--- | :--- | :--- |
| **1** | `run_4_weighted` | `depth=6`, `lr=0.1`, `weight=20` | ROC-AUC: **0.7075**<br>Recall: **0.3455** | **Лучший результат.** Баланс весов заставил модель активно искать фрод. |
| **2** | `run_5_overfit` | `depth=12`, `lr=0.01`, `weight=20` | ROC-AUC: **0.7363**<br>Recall: **0.2000** | Усложнение модели при низком lr ухудшило поиск фрода по сравнению с run_4. |
| **3** | `run_2_deeper` | `depth=10`, `lr=0.1`, `weight=1` | ROC-AUC: **0.7384**<br>Recall: **0.0909** | Без баланса весов модель игнорирует редкий класс, несмотря на глубину. |
| **4** | `run_1_baseline` | `depth=6`, `lr=0.1`, `weight=1` | ROC-AUC: **0.7415**<br>Recall: **0.0909** | Базовый уровень. Высокий ROC-AUC, но критически низкий Recall. |
| **5** | `run_3_slower_lr` | `depth=6`, `lr=0.01`, `weight=1` | ROC-AUC: **0.7228**<br>Recall: **0.0000** | Слишком маленькая скорость обучения без баланса весов = модель предсказывает только "не фрод". |

## Итоговый вывод
Сравнив запуски, мы сделали главный вывод: **на метрику Recall сильнее всего повлиял параметр `scale_pos_weight`** (балансировка весов классов).

Без него (Запуски 1, 3, 4) модель стремилась к общему ROC-AUC, но полностью игнорировала редкий класс мошенничества, показывая Recall на уровне 0–9%. Как только мы добавили вес для класса "фрод" (`weight=20` в Запуске 2), модель начала активнее находить аномалии, и Recall вырос до 34.5%. 

Даже при незначительном снижении ROC-AUC (с 0.74 до 0.70), для бизнес-задачи антифрода такой компромисс оправдан, так как пропуск мошенника стоит дороже, чем ложная блокировка. Конфигурацию **Запуска 2 (`run_4_weighted`)** мы фиксируем как базовую (baseline) для дальнейшей работы.
