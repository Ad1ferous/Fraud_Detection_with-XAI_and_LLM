## Лекция 14. Генеративный ИИ и ИИ-агенты

## Архитектура ИИ-агента для проекта "Детекция мошеннических транзакций"

### Задача агента: Ассистент расследования мошенничества
**Цель:** Автоматизировать сбор контекста по подозрительной транзакции и подготовить для аналитика службы безопасности предварительное заключение с рекомендацией (блокировать или разрешить) на основе данных клиента, истории похожих случаев и объяснения ML-модели.

### Инструменты (4 инструмента):
1. `get_transaction_details(transaction_id)` — получает полные данные о транзакции: сумма, время, место, категория мерчанта, статус карты.
2. `get_client_history(client_id, days)` — получает историю операций клиента за указанный период: средний чек, типичные категории трат, частота операций.
3. `search_similar_fraud_cases(amount, merchant_category)` — ищет в базе подтвержденных случаев мошенничества за последние 90 днях со схожими параметрами и возвращает долю подтвержденного фрода.
4. `get_model_explanation(transaction_id)` — запрашивает у XAI-модуля (на базе CatBoost) текстовое объяснение и основные факторы риска для конкретной транзакции.

**Источники данных:** База транзакций банка (PostgreSQL), база подтвержденных случаев фрода, модуль объяснимости модели (XAI).

**Типы запросов:** 
- "Проверить транзакцию #TX-12345 на мошенничество"
- "Почему модель пометила эту операцию как подозрительную?"
- "Найти похожие подтвержденные случаи для суммы 50 000 руб. в категории электроника"

---

### Метрики успеха:
1. **Доля расследований со ссылками на источники** — процент случаев, где агент дал рекомендацию с прямой ссылкой на конкретное правило антифрода или похожий подтвержденный случай (цель: > 90%).
 is measurable and shows the agent is grounding its answers.
2. **Среднее время ручного расследования** — время от получения алерта до принятия решения оператором (цель: снижение с 15 минут до 5 минут на один случай за счет готового резюме).
3. **Согласованность с экспертами** — доля рекомендаций агента, которые совпали с финальным решением старшего аналитика при ретроспективной проверке (цель: > 85% на тестовой выборке из 100 кейсов).

---

### Риски (3 риска):
1. **Галлюцинация правил или фактов** — агент может уверенно сослаться на несуществующее правило антифрода или исказить сумму транзакции. 
   - *Почему это может произойти:* LLM по своей природе генерирует текст, а не извлекает жесткие факты. Если системный промпт не запрещает выдумывать данные и не требует строгой привязки к ответам инструментов, агент может "придумать" обоснование.

2. **Неправильный выбор инструмента или зацикливание** — агент может многократно вызывать `get_client_history`, игнорируя поиск похожих случаев фрода, и не прийти к финальному ответу.
   - *Почему это может произойти:* Если в описании инструментов (в промпте) нечетко указаны условия их применения, или если агент не получает явного сигнала о том, что собранных данных уже достаточно для вывода.

3. **Использование устаревших данных** — агент может оперировать правилами антифрода или историей клиента полугодовой давности, когда мошенники уже сменили схему.
   - *Почему это может произойти:* Если инструменты агента обращаются к кэшированным данным без проверки времени последнего обновления, или если база подтвержденных случаев фрода обновляется с большой задержкой.

---

### Цикл ReAct (2 полные итерации + завершение)

**Запрос аналитика:** "Проверить транзакцию #TX-78945 на мошенничество"

**Итерация 1:**
- **Рассуждение:** Чтобы начать анализ, мне нужно получить базовую информацию о самой транзакции: сумма, время, категория и данные клиента. Без этого я не могу оценить риск.
- **Действие:** Вызываю инструмент `get_transaction_details("TX-78945")`
- **Результат:** 
  ```json
  {
    "transaction_id": "TX-78945",
    "client_id": "CL-456",
    "amount": 50000,
    "currency": "RUB",
    "timestamp": "2026-11-02 23:47:00",
    "merchant_category": "electronics",
    "location": "online"
  }
  ```

**Итерация 2:**
- **Рассуждение:** Сумма 50 000 руб. для категории "электроника" выглядит нетипично. Мне нужно проверить, каковы обычные траты этого клиента, и есть ли в базе похожие подтвержденные случаи мошенничества с такими параметрами.
- **Действие:** Вызываю инструменты `get_client_history("CL-456", days=30)` и `search_similar_fraud_cases(amount=50000, merchant_category="electronics")`
- **Результат:** 
  ```json
  {
    "client_history": {
      "avg_check_30d": 3500,
      "typical_categories": ["products", "transport", "cafes"],
      "electronics_purchases": 0
    },
    "similar_cases": {
      "total_found": 12,
      "confirmed_fraud": 9,
      "fraud_percentage": 75
    }
  }
  ```

**Завершение (Итоговый ответ):**
- **Рассуждение:** Риск крайне высокий. Сумма транзакции превышает средний чек клиента (3 500 руб.) более чем в 14 раз. Клиент ранее не совершал покупок в категории "электроника". 75% похожих случаев за последние 90 дней были подтверждены как мошенничество. Я запрошу объяснение модели для финального резюме.
- **Действие:** Вызываю инструмент `get_model_explanation("TX-78945")`
- **Результат:** Модель присвоила риск 0.92. Главные факторы: аномальная сумма относительно истории, новое время суток (ночь), новая категория мерчанта.
- **Финальный ответ аналитику:** 
  - **Рекомендация:** БЛОКИРОВАТЬ транзакцию и инициировать звонок клиенту.
  - **Основание:** 
    1. Превышение среднего чека в 14 раз.
    2. Первая покупка в новой категории мерчанта.
    3. 75% похожих случаев (9 из 12) подтверждены как фрод.
    4. Оценка модели: 0.92 (факторы: сумма, время, категория).
  - **Ссылки на источники:** Правило антифрода #7 ("Сумма > 10x от среднего чека"), запись в базе фрода #FR-2341.

### Что мы сделали:
1. Спроектировали архитектуру ИИ-агента для помощи аналитикам службы безопасности, определив его цель и 4 конкретных инструмента.
2. Установили 3 измеримые метрики успеха, которые покажут реальную пользу агента для бизнеса.
3. Выявили 3 конкретных риска (галлюцинации, зацикливание, устаревшие данные) и объяснили причины их возникновения.
4. Описали текстовый цикл ReAct с двумя полными итерациями, где на каждом шаге агент рассуждает, выбирает инструмент, получает результат и движется к финальному обоснованному выводу.
